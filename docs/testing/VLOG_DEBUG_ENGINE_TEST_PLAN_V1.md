# Vlog Wizard デバッグエンジン試験計画 V1

## 目的

Vlog Wizardの主要導線を、正常操作だけでなく、連打、通信切断、離脱・復帰、状態ずれ、再実行まで含めて検証する。

対象導線：

```text
構成
→ プレビュー書き出し
→ プレビュー再生・確認
→ 最終版書き出し
→ 最終版確認
→ 保存先を選んで保存
```

## リリース停止条件

次のいずれかが1件でも残る場合は公開・本番扱いを止める。

- ボタンが押せない、または別の操作になる
- 同じ書き出しが二重起動する
- Cloud Run完了後も画面が永久にRUNNINGのままになる
- 通信切断をジョブ失敗と誤判定する
- プレビューで確認した内容と最終版が大きく異なる
- 編集内容または対象プロジェクトを取り違える
- 最終成果物へ到達・再生・保存できない

## P0：必須実機試験

### VLOG-P0-01 通常導線の完走

**前提**：`01-segment-smoke-v3`を読み込み、書き出し可能な状態にする。

**操作**：

1. 「プレビューを書き出す」を1回押す。
2. 承認画面で内容と上限額を確認してOKを押す。
3. 工程1/7から7/7まで進むことを確認する。
4. 自動で書き出し画面へ移動する。
5. 「プレビューを再生して確認」を押す。
6. 画面内プレーヤーで動画を再生する。
7. 「問題なし・最終版を書き出す」を押す。
8. 最終版の承認後、工程7/7まで待つ。
9. 最終版を再生し、「保存先を選んで保存」を押す。

**合格条件**：途中で迷路、無反応、ダウンロード誤発火、真っ暗画面がなく、1本の最終MP4を保存できる。

### VLOG-P0-02 連打・二重実行防止

**操作**：プレビュー書き出しボタンを素早く5回押す。最終版ボタンでも同じ操作を行う。

**観察点**：

- 受理表示は即時に出る
- prepare / approve / dispatchは各1回
- Cloud Run execution IDは1個
- 生成物も1個
- 画面全体は操作不能にならない

**合格条件**：重複処理を開始せず、「すでに処理中」が表示される。

### VLOG-P0-03 処理中離脱・復帰

**操作**：工程5/7のRUNNING中に、構成・音声・字幕の各タブへ移動し、Safariを一度バックグラウンドへ送った後、書き出し画面へ戻る。

**合格条件**：同じrequest IDとexecution IDを復元し、新しいジョブを作らず、完了結果へ到達する。

### VLOG-P0-04 通信切断からの再接続

**操作**：RUNNING中に機内モードを約15秒有効にし、解除する。

**合格条件**：

- `Load failed`を最終失敗扱いしない
- 「通信を再接続中」と表示する
- 「今すぐ再接続」が押せる
- Cloud Run側のジョブを重複起動しない
- 復旧後に同じ処理の完了へ到達する

### VLOG-P0-05 完了済みジョブの状態補正

**前提**：Cloud Run側は成功し、GCSに成果物があるが、ローカルhandoffを意図的にRUNNINGのままにする。

**操作**：「状態を読み込む」またはステータスAPIを呼ぶ。

**合格条件**：実行結果を照合してCOMPLETEDへ補正し、確認画面へ進める。永遠にRUNNING表示を続けない。

### VLOG-P0-06 プレビュー再生と保存の分離

**操作**：「プレビューを再生して確認」を押す。

**合格条件**：Safariのダウンロード確認ではなく専用画面内の`video`で再生する。最終版完成後の保存操作だけがダウンロードを開始する。

### VLOG-P0-07 プレビューから最終版への接続

**操作**：プレビュー再生画面の「問題なし・最終版を書き出す」を1回押す。

**合格条件**：

- ボタンが押せる
- 書き出し画面へ戻る
- `action=final`は一度だけ消費される
- 最終版の承認画面が開く
- 再読み込みしても勝手にもう一度起動しない

### VLOG-P0-08 プレビュー・最終版整合

**比較項目**：

- セグメント順
- 動画の総尺
- 各区間の開始・終了
- 元音声／後付け音声／無音の選択
- 字幕モードと字幕区間
- オープニング・画面収録・エンディングの存在
- 主要フレーム

**合格条件**：画質差を除き、確認した構成と最終版の内容が一致する。

## P1：異常系・復旧試験

### VLOG-P1-01 承認キャンセル

承認ダイアログでキャンセルする。Cloud Runが起動せず、工程3/7で安全に停止し、再度実行できること。

### VLOG-P1-02 承認の期限切れ・二重使用

同じrequest IDの承認を期限切れ後および消費後に再利用する。2回目を拒否し、新規Security Gateからやり直すこと。

### VLOG-P1-03 prepare中の通信切断

工程2/7の素材正規化中に通信を切る。途中生成物やhandoffを壊さず、エラー内容が確認でき、再実行時に二重ステージングを誤利用しないこと。

### VLOG-P1-04 dispatch直後の画面終了

Cloud Run投入直後にSafariタブを閉じ、同じURLを開き直す。ジョブを再投入せず、既存executionを追跡すること。

### VLOG-P1-05 旧成果物の表示

旧`vlog.mp4`が存在する状態で新しい最終版を書き出す。処理中は「旧版」または「更新中」と明示し、新版完成前に旧版を新しい完成物として扱わないこと。

### VLOG-P1-06 失敗後の再試行

意図的にCloud Run Jobを失敗させ、エラー表示後に再試行する。古いrequestと新しいrequestが混ざらず、生成物が破損・重複しないこと。

### VLOG-P1-07 キャッシュ更新

JSのバージョンを更新後、通常URLとクエリ付きURLを開く。最新の`rts-progress-overlay.js`、`compose-cloud-render.js`、`output-review-flow.js`が読み込まれ、旧UIが残らないこと。

### VLOG-P1-08 オーバーレイ非阻害

処理中、再接続中、失敗中の各オーバーレイ表示で、タブ移動、戻る、状態読込など通常の画面操作が可能であること。オーバーレイ自身の操作ボタンだけがクリックを受け取ること。

## 人間専用テスト

| No. | 前提 | 操作 | 観察点 | 合格条件 |
|---:|---|---|---|---|
| H1 | 初見 | 書き出し画面を開く | 次の操作 | 5秒以内に「まずプレビュー」と判断できる |
| H2 | 工程表示中 | 工程5/7を見る | 現在地 | 何を処理中で残り何工程か説明できる |
| H3 | プレビュー完成 | 確認画面を見る | 次の分岐 | 修正／最終版の二択が明確 |
| H4 | iPhone片手操作 | 全導線を押す | タップ性 | 誤操作せず押せる、ボタンが隠れない |
| H5 | 最終版完成 | 保存する | 保存先 | Safariの保存先選択まで迷わない |
| H6 | 動画視聴 | 最初から最後まで見る | 感覚品質 | 音ズレ、字幕ズレ、不自然な切断、黒画面がない |

## 証拠として残すもの

各試験で次を保存する。

- 開始前・処理中・完了／失敗時のスクリーンショット
- project、request ID、execution ID
- API status JSON
- Cloud Runの終了状態
- GCS成果物名・サイズ・生成時刻
- Safari上の実結果
- 合否と再現手順

## 自動化の分担

- `pytest`：API状態遷移、承認の単一使用、reconcile、成果物存在確認
- Playwright WebKit：ボタン接続、連打、画面遷移、離脱・復帰、再読み込み
- `ffprobe` / `ffmpeg`：尺、ストリーム、音声、主要フレーム、プレビュー・最終版比較
- iPhone Safari：タップ性、保存先選択、バックグラウンド復帰、感覚品質
