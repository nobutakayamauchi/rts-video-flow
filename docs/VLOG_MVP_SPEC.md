# 限界開発 Vlog MVP 仕様書

## 1. 目的

限界開発のブランドと実在感を補強するため、iPhoneで撮影した短い外カメラ映像、必要な場面だけの画面収録、作業中のスクリーンショットを、最小限の手作業で一本のVlogへ変換する。

YouTube運用そのものを主目的にはしない。限界開発の作業記録を、映像・字幕・文章へ再利用するための共通出力パーツとして扱う。

## 2. 基本方針

- 撮影はiPhone標準のカメラ・画面収録・スクリーンショットを使う
- 撮影機能そのものは自作しない
- 普段はスクリーンショット中心とし、画面収録は短いデモや動作証拠に限定する
- 長時間の画面収録、凝った編集、複雑なトランジションは行わない
- 既存の文字起こし・字幕分割・Remotion出力を再利用する
- 最終確認と公開判断は人間が行う

## 3. 想定入力

1案件を1フォルダとして扱う。

```text
projects/vlog-001/
├── config.json
├── opening/          # 外カメラの冒頭動画 0〜1本
├── screen-recording/ # 短い画面収録 0〜複数本
├── screenshots/      # 時系列に並べる画像 1枚以上
├── ending/           # 外カメラの締め動画 0〜1本
└── notes.md          # 任意。今日やったこと・補足
```

ファイル名は `01-`, `02-` のような連番を付け、表示順を固定する。

## 4. 想定出力

```text
output/vlog-001/
├── vlog.mp4
├── subtitles.srt
├── subtitles.json
├── transcript.md
├── youtube-description.md
├── title-and-tags.md
├── note-draft.md
└── processing-report.md
```

## 5. MVPで必須の機能

### 5.1 素材検査

- 対応拡張子を検査する
- 画像・動画の並び順を確定する
- 個人情報や秘密情報がないことを人間が確認したか、設定値で明示する
- 素材不足・破損・重複を報告する

### 5.2 動画構成

固定テンプレートを使う。

```text
外カメラ冒頭
↓
短い画面収録（任意）
↓
スクリーンショットを順番に表示
↓
外カメラ締め（任意）
```

スクリーンショットは既定5秒表示。必要に応じて設定で変更できる。演出は軽いパン・ズームまたは静止表示のみ。

### 5.3 音声・文字起こし

- 既存の `extract_audio.sh` を利用する
- 既存の `transcribe.py` を利用する
- Whisper `large-v3`、資源不足時は `medium` へフォールバックする
- 全文をMarkdownへ保存する

### 5.4 字幕

- 既存の `segment_subtitles.py` を利用する
- 日本語字幕は最大2行、1行30文字以内を基本とする
- Remotion用JSONを生成する
- YouTube登録用SRTも生成する
- 長尺Vlogでは字幕焼き込みを任意とし、SRT出力を標準にする

### 5.5 レンダリング

- 既存Remotion構成を拡張する
- 横動画を標準とする
- 元映像の縦横比が異なる場合は、黒背景またはぼかし背景で収める
- 音量の急変を抑える
- 出力はH.264/AACのMP4を標準とする

### 5.6 文章生成用素材

AIへ渡せる下書き素材として、以下を機械的に生成する。

- 全文文字起こし
- 動画時間
- 使用素材一覧
- 章候補とタイムスタンプ
- 切り抜き候補区間

タイトル、概要欄、note本文の最終生成はAIで行うが、事実・リンク・固有名詞は人間が確認する。

### 5.7 一括実行

最終的な利用形は次を目標とする。

```bash
./scripts/process_vlog.sh projects/vlog-001
```

途中失敗時は再実行でき、完了済み工程を再利用する。

## 6. config.json

```json
{
  "project_id": "vlog-001",
  "title_seed": "限界開発Vlog 第1回",
  "screenshot_seconds": 5,
  "include_burned_subtitles": false,
  "silence_cut": false,
  "orientation": "landscape",
  "privacy_reviewed": false,
  "links": {
    "limit_development": "https://nobutakayamauchi.github.io/RS-AI-limit-development/",
    "docs": "https://nobutakayamauchi.github.io/RS-AI-limit-development/docs/"
  }
}
```

`privacy_reviewed` が `true` でない場合、最終レンダリングは停止する。

## 7. 今回追加する機能

既存コードに対して、以下を追加する。

1. プロジェクトフォルダ方式
2. スクリーンショットの自動整列
3. 外カメラ・画面収録・スクショの固定テンプレート
4. SRT生成
5. transcript.md生成
6. processing-report.md生成
7. 一括実行スクリプト
8. プライバシー確認ゲート
9. 再実行可能な工程管理

## 8. MVPでは作らないもの

- iPhone内の独自撮影アプリ
- YouTube APIによる自動投稿
- 高度なタイムライン編集UI
- 顔追跡
- 多数のトランジション
- BGM自動選曲
- サムネイル自動合成
- Shorts自動量産
- 本格的な色補正

必要性が実際のドッグフーディングで確認できた場合のみ追加する。

## 9. ドッグフーディング手順

第1回Vlog自体を、このMVPの検証素材にする。

1. 何もない場所を外カメラで撮る
2. iPhoneの画面収録を短時間だけ実演する
3. 実際の作業スクリーンショットを3〜8枚用意する
4. 今回作ったVlogパーツを使って動画化する
5. 字幕・文字起こし・概要欄素材を生成する
6. 人間が確認してYouTubeへ手動投稿する
7. 作業時間、端末負荷、修正回数を記録する
8. 次版で必要な機能だけ追加する

## 10. 最低成功条件

- 1つのプロジェクトフォルダからMP4を生成できる
- SRTと全文文字起こしを生成できる
- スクリーンショットが指定順で表示される
- 外カメラと画面収録を同じ動画へ含められる
- 15〜30分の素材を、手作業30分以内で投稿準備まで進められる
- 機密情報確認を通らない限り最終出力しない
- 第1回Vlogを実際に公開できる

## 11. 完成後の位置づけ

このパーツは動画制作事業の本体ではない。

**限界開発の作業記録から、映像・字幕・文章を最小労力で作る共通出力機能**として維持する。
