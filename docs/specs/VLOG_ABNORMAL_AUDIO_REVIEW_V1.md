# Vlog Abnormal Audio Review v1

Status: FROZEN FOR IMPLEMENTATION
Branch: `feat/narration-segments-v1`

## Goal

完成動画に、視聴者へ強い不快感・驚愕・聴覚上の危険を与える可能性がある音が含まれていないか、公開前に確認できるようにする。

本機能は内容を自動検閲するものではない。異常または要注意の候補区間を提示し、利用者が必要な音か、処理すべき音かを判断するための安全ゲートとする。

## 1. Audit timing

- 元音声、後入れ音声、BGM、MIX、ピー音、境界ジャンプカットをすべて反映した完成動画を検査する
- 検査は最終書き出し直後、完成扱いの確定前に実行する
- 元素材、元録音、完成動画を自動で削除または上書きしない

## 2. Detection layers

### 2.1 Deterministic technical hazards

信号解析で比較的客観的に判定できるもの。

- 音割れまたは連続クリッピング
- 突発的な大音量ピーク
- 全体と比べて極端に大きい区間
- 15kHz以上の狭帯域へ集中した持続高周波
- 機器発振音、モスキート音に近い持続トーン
- 解析不能、音声ストリーム破損、検査処理失敗

これらは `TECHNICAL_HAZARD` として扱う。

### 2.2 Context-sensitive acoustic events

音響イベント分類で候補を出すが、内容上必要な場合があるもの。

- 子どもの激しい泣き声、ギャン泣き
- 叫び声、怒声、罵声に近い強い発声
- 金切り声、甲高い持続発声
- 緊急地震速報、警報、サイレン、ブザーに近い音
- その他、長く続く強い苦痛音または警戒音

これらは `REVIEW_REQUIRED` として扱う。

分類名は断定表現にせず、必ず「候補」と表示する。

### 2.3 Subjective unpleasant-sound candidates

人によって不快さが異なり、作品上必要な場合もある音。

- 黒板、ガラス、金属を引っかくような擦過音
- 発泡スチロール、風船、硬質素材の摩擦音
- 咀嚼音、口を鳴らす音、いわゆるクチャ音
- 鼻すすり、強い呼吸音、反復する口音
- 反復クリック、打音、摩擦音

これらは `PREFERENCE_REVIEW` として扱う。存在しただけでは警告せず、明らかに長い、反復している、動画内の占有率が高い場合にだけ要確認とする。

## 3. Detection contract

各候補には最低限、次を保存する。

- `category`
- `label`
- `startSeconds`
- `endSeconds`
- `durationSeconds`
- `confidence`
- `peakLevel`
- `source`（元音声、後入れ、BGM、最終MIXなど）
- `severity`
- `detectorVersion`
- `mergedEventCount`
- `windowCandidateSeconds`
- `windowSeconds`
- `occupancyRatio`

短い一瞬の音だけで警告を乱発しない。持続時間、音量、分類信頼度、反復回数、時間窓内の占有率を組み合わせて候補化する。

## 4. Rough persistence and density rules

初期版は精密な心理評価を狙わず、「明らかに入りすぎている」ものだけを荒く拾う。

### 4.1 Event merging

- 同じ種類の候補が0.75秒以内に再発した場合は一つの候補区間へまとめる
- 細切れの候補を大量表示しない
- まとめた区間には発生回数と実際の候補音合計秒数を保存する

### 4.2 Default thresholds

- 単発かつ1.5秒未満は原則 `INFO` とし、通常の要確認には出さない
- ただし極端な大音量、音割れ、高周波など技術的危険条件を満たす場合は別扱いとする
- 同種音が連続3.0秒以上続いた場合は `REVIEW`
- 任意の15秒窓で同種候補の合計が5.0秒以上の場合は `REVIEW`
- 同種音が連続8.0秒以上続いた場合は `STRONG_REVIEW`
- 任意の30秒窓で同種候補の合計が10.0秒以上の場合は `STRONG_REVIEW`
- 一つの素材内で候補音が30%以上を占め、かつ合計6.0秒以上ある場合も `STRONG_REVIEW`

これらは実素材による誤検知確認後に調整可能な初期値とする。しきい値はコードへ直書きせず、検出器設定として保持する。

### 4.3 Example

```text
クチャ音候補が0.4秒ずつ3回、10秒間に存在
→ 合計1.2秒なので通常は表示しない

クチャ音候補が15秒間に合計6.2秒存在
→ 繰り返し入りすぎとして要確認

擦過音が9秒間連続
→ 強い要確認
```

## 5. Severity and action

### BLOCK

- 連続クリッピング
- 明らかに危険な大音量
- 高確信の持続高周波
- 検査自体の失敗（厳格モード）

通常モードでは強い警告、厳格モードでは完成扱いを止める。

### STRONG_REVIEW

- 文脈依存音または主観的不快音が長時間連続している
- 一定時間内に繰り返し発生し、占有率が高い

完成動画は保持するが、候補区間を目立つ形で表示し、確認が終わるまで「強い要確認」とする。

### REVIEW

- 激しい泣き声候補
- 叫び声、怒声、金切り声候補
- 緊急警報、サイレン候補
- 擦過音、咀嚼音などが初期しきい値を超えた候補

完成動画は保持するが、利用者による確認が終わるまで「要確認」と表示する。

### INFO

- 短時間または低信頼度の候補
- 作品上の効果音である可能性が高い音
- 主観的不快音候補だが、長さ・反復・占有率が初期しきい値未満のもの

記録のみ行い、完成扱いを止めない。

## 6. Automatic candidate review UI

自動検出された候補ごとに次を表示する。

```text
00:12.4–00:18.6
咀嚼音・口音に近い音の候補
15秒間の候補合計: 6.2秒
発生回数: 9回
信頼度: 0.82
音量: 中

[小音量で確認]
[必要な音として承認]
[この音だけ無音化]
[音量を下げる]
[区間ごと削除]
[ピー音で伏せる]
[素材を差し替える]
```

- 確認再生は初期音量を低くする
- 「必要な音として承認」した候補は、承認者と日時を記録する
- 「この音だけ無音化」は映像尺を維持する
- 「区間ごと削除」は映像と音声を同じ範囲で切り、字幕、ピー音区間、タイムライン開始位置を同期更新する
- 削除・無音化・音量低下は出力用コピーへ適用し、元素材を保持する
- 処理後は再検査する
- 要確認候補を黙って無視したまま公開済み扱いにしない

## 7. Manual press-to-mark discomfort review

自動分類の精度に依存せず、利用者自身が聞いて不快だと感じた区間を簡単に指定できる手動レビューを必須の逃げ道として用意する。

### 7.1 Review interaction

- 完成MIXまたは選択素材を低音量で再生する
- 画面中央に片手で押せる大きな `嫌な音を記録` ボタンを表示する
- ボタンを押した時点を候補開始、離した時点を候補終了として記録する
- 押している間は色、振動、経過秒数で記録中であることを示す
- iPhoneの画面スクロールや長押しメニューを発生させず、`pointerdown` / `pointerup` / `pointercancel` を安全に処理する
- 再生停止、画面離脱、着信などで操作が中断された場合は、開いたままの候補区間を勝手に確定せず確認を求める

### 7.2 Reaction-delay compensation

人が嫌だと感じてから押すまでの反応遅れを補う。

- 初期値として開始時刻を押下位置の0.4秒前へ戻す
- 終了時刻を指を離した位置の0.2秒後へ伸ばす
- 0秒未満または素材終了後へはみ出さないよう制限する
- 補正値は内部設定として保持し、後から実機テストで変更できる
- 0.3秒未満の短いタップは、タップ位置を中心とする前0.5秒・後0.5秒の候補として扱う

### 7.3 Manual range correction

記録後は必ず秒数を修正できるようにする。

```text
開始 00:12.3  [-0.5] [-0.1] [+0.1] [+0.5]
終了 00:14.8  [-0.5] [-0.1] [+0.1] [+0.5]

[前後1秒を含めてループ確認]
[この範囲で確定]
```

- 開始秒、終了秒を数値入力でも指定できる
- 0.1秒単位で微調整できる
- 開始は終了より前でなければならない
- 前後1秒のハンドルを付けたループ確認を基本とする
- 既存候補と0.75秒以内で重なる場合は統合候補を提案するが、勝手には統合しない

### 7.4 Actions for one marked range

確定した手動候補には次を用意する。

- `問題なしとして残す`
- `音量だけ下げる`
- `この音だけ無音化する`
- `ピー音で伏せる`
- `映像と音声を区間ごと削除する`
- `素材全体を差し替える`

すべて非破壊処理とし、元素材と元完成動画を保持する。

### 7.5 Multiple marks and batch handling

- 手動候補の件数、合計秒数、素材内占有率を常時表示する
- 近接候補を一件へまとめる操作を用意する
- 複数候補を選択し、同じ処理を一括適用できる
- `すべて無音化`、`すべて区間削除`、`すべて音量低下` を確認付きで実行できる
- 一括区間削除は時間の後ろ側から適用し、時刻ずれを防ぐ
- 各削除後に字幕、ピー音区間、候補区間、素材時間、後続タイムラインを再計算する

### 7.6 Replace-or-discard recommendation

修正箇所が多すぎる場合は、一件ずつ直すより素材を捨てて撮り直す選択肢を目立たせる。

初期の荒い目安は次とする。

- 手動候補が5件以上、または合計が素材の15%以上: `差し替えも検討` を表示する
- 手動候補が10件以上、合計が素材の30%以上、または削除後の内容が成立しにくい場合: `素材差し替えを推奨` を強く表示する
- 上記は自動削除の条件ではなく、利用者への提案だけとする
- `素材をゴミ箱へ移動して差し替える` は明示確認後に実行する
- 素材削除は復元可能なゴミ箱へ移動し、プロジェクト全体を削除しない

## 8. Automatic processing boundaries

- 泣き声、怒声、叫び声、警報音、擦過音、咀嚼音を自動削除しない
- 自動ピー音化しない
- 自動でBGMへ置換しない
- 誤判定で内容を壊さないことを優先する
- 音量リミットやノッチ補正も、実サンプル検証前は警告と提案に留める
- 利用者が明示的に処理を選んだ場合だけ、無音化、減衰、区間削除を実行する

## 9. False-positive safeguards

- BGMの歌声、シンバル、効果音だけで叫び声や警報と断定しない
- 赤ちゃんの笑い声を泣き声と断定しない
- 食事動画やASMRでは咀嚼音を「必要な音」として承認できる
- 実際の緊急速報を扱う解説動画では警報音を「必要な音」として承認できる
- 一瞬の食器音や子音をクチャ音と断定しない
- 同一候補を細切れで大量表示せず、近接区間を一件へまとめる
- 分類モデル、しきい値、検出バージョンをレポートへ残す

## 10. Output

最終出力フォルダへ次を保存する。

- `AUDIO_SAFETY.md`
- `audio-safety.json`
- 自動候補区間一覧
- 手動候補区間一覧
- 発生回数、時間窓内合計秒数、占有率
- 利用者の承認または処理結果
- 手動範囲の元時刻、補正後時刻、最終確定時刻
- 再検査結果

## 11. v1 implementation boundary

### v1で必須

- 音割れ、大音量、持続高周波の技術検査
- 音響イベント分類器を差し込める共通インターフェース
- 候補区間、信頼度、重要度の記録
- 近接候補の統合、持続時間、反復、占有率による荒い判定
- 警告表示と人による承認状態
- 押している間を記録する手動不快音マーキング
- 反応遅れ補正、0.1秒単位の開始終了修正、区間ループ確認
- 無音化、減衰、ピー音、区間削除を非破壊で適用できる編集契約
- 複数候補の一括処理と素材差し替え導線
- 検査失敗を成功扱いしない

### 実モデル検証後に有効化

- 激しい泣き声
- 叫び声、怒声、金切り声
- 緊急警報、サイレン
- 黒板、ガラス、金属などの擦過音
- 咀嚼音、口音、鼻すすり、強い呼吸音

実モデルが未導入または利用不能の場合は「未検査」と明示し、検出できたように見せない。

## 12. Acceptance checks

- 技術的異常、文脈依存音、主観的不快音を別カテゴリで扱う
- 単発の短い候補で警告を乱発しない
- 同種音が長時間または高密度で続いた場合に要確認となる
- 近接する候補が一つの区間へ統合される
- 泣き声、警報音、咀嚼音などが自動削除されない
- 候補区間を低音量で確認できる
- 再生しながらボタンを押している間を候補として記録できる
- 反応遅れを補正し、開始終了を0.1秒単位で修正できる
- 手動候補を前後ハンドル付きでループ確認できる
- 必要な音として承認できる
- 音量低下、音だけの無音化、ピー音、映像を含む区間削除を選べる
- 複数候補を一括処理できる
- 候補数と占有率が多い場合に素材差し替えが提案される
- 素材削除は復元可能で、プロジェクト全体を誤削除しない
- 区間削除後も字幕、ピー音、候補区間、タイムラインが同期する
- 処理後に再検査できる
- 検査不能をPASSとして表示しない
- 誤判定時に元動画と完成動画が保持される
