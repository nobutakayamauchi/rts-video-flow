# Vlog Abnormal Audio Review v1

Status: FROZEN FOR IMPLEMENTATION
Branch: `feat/narration-segments-v1`

## Goal

完成動画に、視聴者へ強い不快感・驚愕・聴覚上の危険を与える可能性がある音が含まれていないか、公開前に確認できるようにする。

本機能は内容を自動検閲するものではない。異常または要注意の候補区間を提示し、利用者が必要な音か、処理すべき音かを判断するための安全ゲートとする。

## 1. Audit timing

- 元音声、後入れ音声、BGM、MIX、ピー音、境界ジャンプカットをすべて反映した完成動画を検査する
- 検査は最終書き出し直後、完成扱いの確定前に実行する
- 元素材、元録音、完成動画を自動で削除または上書きしない

## 2. Detection layers

### 2.1 Deterministic technical hazards

信号解析で比較的客観的に判定できるもの。

- 音割れまたは連続クリッピング
- 突発的な大音量ピーク
- 全体と比べて極端に大きい区間
- 15kHz以上の狭帯域へ集中した持続高周波
- 機器発振音、モスキート音に近い持続トーン
- 解析不能、音声ストリーム破損、検査処理失敗

これらは `TECHNICAL_HAZARD` として扱う。

### 2.2 Context-sensitive acoustic events

音響イベント分類で候補を出すが、内容上必要な場合があるもの。

- 子どもの激しい泣き声、ギャン泣き
- 叫び声、怒声、罵声に近い強い発声
- 金切り声、甲高い持続発声
- 緊急地震速報、警報、サイレン、ブザーに近い音
- その他、長く続く強い苦痛音または警戒音

これらは `REVIEW_REQUIRED` として扱う。

分類名は断定表現にせず、必ず「候補」と表示する。

## 3. Detection contract

各候補には最低限、次を保存する。

- `category`
- `label`
- `startSeconds`
- `endSeconds`
- `durationSeconds`
- `confidence`
- `peakLevel`
- `source`（元音声、後入れ、BGM、最終MIXなど）
- `severity`
- `detectorVersion`

短い一瞬の音だけで警告を乱発しない。持続時間、音量、分類信頼度を組み合わせて候補化する。

## 4. Severity and action

### BLOCK

- 連続クリッピング
- 明らかに危険な大音量
- 高確信の持続高周波
- 検査自体の失敗（厳格モード）

通常モードでは強い警告、厳格モードでは完成扱いを止める。

### REVIEW

- 激しい泣き声候補
- 叫び声、怒声、金切り声候補
- 緊急警報、サイレン候補

完成動画は保持するが、利用者による確認が終わるまで「要確認」と表示する。

### INFO

- 短時間または低信頼度の候補
- 作品上の効果音である可能性が高い音

記録のみ行い、完成扱いを止めない。

## 5. User review UI

候補ごとに次を表示する。

```text
00:12.4–00:15.8
子どもの激しい泣き声の候補
信頼度: 0.89
音量: 大

[小音量で確認]
[必要な音として承認]
[この区間を無音化]
[ピー音で伏せる]
[素材を差し替える]
```

- 確認再生は初期音量を低くする
- 「必要な音として承認」した候補は、承認者と日時を記録する
- 処理後は再検査する
- 要確認候補を黙って無視したまま公開済み扱いにしない

## 6. Automatic processing boundaries

- 泣き声、怒声、叫び声、警報音を自動削除しない
- 自動ピー音化しない
- 自動でBGMへ置換しない
- 誤判定で内容を壊さないことを優先する
- 音量リミットやノッチ補正も、実サンプル検証前は警告と提案に留める

## 7. False-positive safeguards

- BGMの歌声、シンバル、効果音だけで叫び声や警報と断定しない
- 赤ちゃんの笑い声を泣き声と断定しない
- 実際の緊急速報を扱う解説動画では「必要な音」として承認できる
- 同一候補を細切れで大量表示せず、近接区間を一件へまとめる
- 分類モデル、しきい値、検出バージョンをレポートへ残す

## 8. Output

最終出力フォルダへ次を保存する。

- `AUDIO_SAFETY.md`
- `audio-safety.json`
- 候補区間一覧
- 利用者の承認または処理結果
- 再検査結果

## 9. v1 implementation boundary

### v1で必須

- 音割れ、大音量、持続高周波の技術検査
- 音響イベント分類器を差し込める共通インターフェース
- 候補区間、信頼度、重要度の記録
- 警告表示と人による承認状態
- 検査失敗を成功扱いしない

### 実モデル検証後に有効化

- 激しい泣き声
- 叫び声、怒声、金切り声
- 緊急警報、サイレン

実モデルが未導入または利用不能の場合は「未検査」と明示し、検出できたように見せない。

## 10. Acceptance checks

- 技術的異常と文脈依存の要注意音を別カテゴリで扱う
- 泣き声や警報音が自動削除されない
- 候補区間を低音量で確認できる
- 必要な音として承認できる
- 無音化、ピー音、差し替え後に再検査できる
- 検査不能をPASSとして表示しない
- 誤判定時に元動画と完成動画が保持される
