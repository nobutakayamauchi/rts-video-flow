# Vlog Camera Audible Privacy Signal v1

Status: FROZEN FOR IMPLEMENTATION
Branch: `feat/narration-segments-v1`

## Goal

インカメラまたはアウトカメラが意図せず、または周囲へ分かりにくい状態で起動・録画されることを防ぐため、カメラ利用時に消せない音声合図と視覚表示を必須にする。

本機能は盗撮を技術的に完全排除できると断定するものではない。Webアプリでは端末音量、消音状態、Bluetooth・有線出力先、改変されたクライアント等まで完全には制御できないため、音、画面表示、OS権限、バックグラウンド停止、監査記録を重ねる多層対策とする。

## 1. Explicit user action

- インカメラとアウトカメラは、それぞれ明示されたボタンを利用者が押した場合だけ起動する
- ページ表示、素材種別変更、プロジェクト読込、画面復帰等を契機に自動起動しない
- カメラ・マイク権限要求は、起動ボタン操作と起動音処理の後に実行する
- URLパラメータ、Local Storage、Cookie、管理設定等による自動起動または無音起動を設けない

## 2. Non-disableable signal sequence

### 2.1 Camera opening

1. 利用者が `インカメを起動` または `アウトカメを起動` を押す
2. 画面へ `カメラを起動します` を大きく表示する
3. 起動音として短い二音の上昇音 `ポッ・ポッ` を再生する
4. 音声再生APIが開始・完了したことを確認する
5. 確認後にだけカメラとマイクを要求し、プレビューを開始する

- 起動音の再生処理が失敗、拒否、タイムアウトした場合はカメラを開かない
- エラー時は `起動音を再生できないため、カメラを開けません` と表示する
- 起動音が鳴り終わる前にカメラ・マイクを開かないため、起動音を録音素材へ混入させない

### 2.2 Recording start

- 録画開始ボタンを押したときは、開始を示す短い一音を鳴らす
- 録画開始音が完了してから MediaRecorder を開始する
- 画面上部へ赤色の `● 録画中` 表示と経過時間を常時表示する
- 録画中表示は折りたたみ、非表示、透明化できない

### 2.3 Recording stop

- 録画停止操作では、まず録画データを安全に確定する
- 録画停止後に、開始音と区別できる短い下降音を鳴らす
- 停止音の成否にかかわらず、録画処理は停止し、データを失わない

### 2.4 Camera closing

- カメラ利用終了時は全MediaStreamTrackを停止する
- 停止確認後に短い二音の下降音 `ポッ・ポッ` を鳴らす
- カメラ終了音を鳴らすためにカメラ停止を遅らせない
- インカメラとアウトカメラを切り替える場合は、旧ストリームを終了してから終了音、新しい起動音、新ストリーム起動の順で処理する

## 3. No silent-camera option

- アプリ内に起動音、録画開始音、録画終了音、カメラ終了音をOFFにする設定を設けない
- 音量スライダー、ミュートボタン、音声ファイル差替え、開発者向け無音フラグを設けない
- 通常UI、詳細設定、プロジェクト設定、ユーザー設定のいずれからも無効化できない
- 静かな環境でアプリ内カメラを起動できない利用者には、端末で事前に撮影したファイルを選択する導線を案内する

## 4. Web-platform limitation and fail-closed boundary

- Webアプリが確認できるのは、音声再生APIが正常に開始・完了したことまでとする
- 端末本体の実音量、消音状態、接続中のイヤホン、外部出力先、周囲の人が実際に聞こえたかは保証できない
- 音声API自体が失敗した場合は、起動時のみ fail closed としカメラを開かない
- 物理的に聞こえたことを確認できないため、音声合図だけを唯一の盗撮対策として扱わない
- 画面へ `端末の音量と音声出力先を確認してください` と表示する

## 5. Persistent visual safeguards

カメラまたはマイクを使用している間、次を常時表示する。

- 赤い `カメラ使用中` バナー
- 使用中のカメラ種別 `インカメ` / `アウトカメ`
- マイク使用状態
- 録画中かプレビュー中か
- 録画中の経過時間
- 片手で押せる大きな `カメラを終了` ボタン

- プレビューを画面外へ隠した状態で利用を続けない
- CSS、全画面表示、スクロール位置によって使用中表示が見えなくならないよう固定表示とする
- iPhoneが表示するカメラ・マイク使用インジケータを補完するUIとし、置き換えとはみなさない

## 6. Background and interruption behavior

次の場合は録画を止め、カメラ・マイクのトラックを停止する。

- ページが非表示になった
- 別ページへ遷移した
- ブラウザの戻る操作を行った
- 素材種別をカメラ以外へ変更した
- ファイル選択へ切り替えた
- 通話、権限取消、デバイス切断等でストリームが中断した
- 保存処理または重大エラーが発生した

- バックグラウンド録画を継続しない
- 自動再開しない
- 再開には再度の明示操作と起動音を必要とする
- 中断時に録画済みデータが存在する場合は、破棄せず復旧確認を表示する

## 7. Signal implementation contract

- 音はアプリ内Web Audio等で生成し、外部ネットワーク取得へ依存しない
- 音量はアプリ内で意図的に極小化せず、聴覚へ危険を与えない固定レベルとする
- 起動・終了を聞き分けられるよう音程または並びを変える
- 音声信号は短くし、周囲を驚かせる大音量にしない
- 起動音と録画開始音はマイク・録画開始前に完了させ、素材へ混入させない
- 終了音は録画・ストリーム停止後に再生する
- 音声処理の失敗を無視して起動へ進まない

## 8. Audit record

一回のカメラ利用セッションについて、最低限次を記録する。

```json
{
  "sessionId": "camera-session-001",
  "facingMode": "user",
  "cameraRequestedAt": "ISO-8601",
  "openingSignalStatus": "completed",
  "cameraOpenedAt": "ISO-8601",
  "recordingStartedAt": "ISO-8601 or null",
  "recordingStoppedAt": "ISO-8601 or null",
  "cameraClosedAt": "ISO-8601",
  "closingSignalStatus": "completed-or-failed",
  "stopReason": "user-stop",
  "clientVersion": "version"
}
```

- 監査記録へ映像、音声、位置情報を複製しない
- `openingSignalStatus` が成功していないセッションでは `cameraOpenedAt` を持たせない
- 記録は不具合調査と安全確認のために用い、自動公開しない

## 9. Camera session state machine

許可する状態遷移は次のみとする。

```text
IDLE
→ OPENING_SIGNAL
→ REQUESTING_PERMISSION
→ PREVIEW_ACTIVE
→ RECORDING_START_SIGNAL
→ RECORDING
→ RECORDING_STOPPING
→ PREVIEW_ACTIVE
→ CAMERA_CLOSING
→ IDLE
```

- `IDLE` から直接 `PREVIEW_ACTIVE` または `RECORDING` へ遷移しない
- `OPENING_SIGNAL` 失敗時は `IDLE` へ戻る
- `RECORDING` から画面非表示等が発生した場合は停止・保存確認を経て `CAMERA_CLOSING` へ進む
- 二重起動、二重録画、終了処理中の再起動を拒否する

## 10. Acceptance checks

- インカメ・アウトカメの明示操作なしにカメラが起動しない
- 起動音完了前にカメラ・マイクが開かない
- 起動音API失敗時にカメラが開かない
- 録画開始音完了前に録画が始まらない
- 起動音、開始音、停止音、終了音をアプリ内設定で無効化できない
- カメラ使用中の赤い表示が常に見える
- プレビューと録画中を明確に区別できる
- ページ非表示または離脱時にカメラ・録画が停止する
- カメラ終了時に全MediaStreamTrackが停止する
- 終了音失敗がカメラ停止を妨げない
- インカメ・アウトカメ切替時に旧ストリームが残らない
- 起動・録画開始音が保存映像へ混入しない
- 音声API成功を、周囲へ物理的に聞こえた保証として表示しない
- 各セッションの起動・録画・終了状態が監査記録に残る
- 元撮影データを安全機能の都合で削除しない
